## Step 1 — Android `--libc` recipe (proven; re-materialize it)

Zig 0.16 does **not** bundle bionic headers (no `*-android` dir in `lib/zig/libc/include`); an NDK-backed `--libc` file is mandatory, same as iOS. The verified file was saved to the previous session's scratchpad (`.../scratchpad/zig-libc-android.txt`) which may be gone — recreate with these **exact contents** (verified: compiles `<android/log.h>` code AND links a shared object, i.e. crt objects resolve):

```
include_dir=/Users/you/Library/Android/sdk/ndk/26.2.11394342/toolchains/llvm/prebuilt/darwin-x86_64/sysroot/usr/include
sys_include_dir=/Users/you/Library/Android/sdk/ndk/26.2.11394342/toolchains/llvm/prebuilt/darwin-x86_64/sysroot/usr/include/aarch64-linux-android
crt_dir=/Users/you/Library/Android/sdk/ndk/26.2.11394342/toolchains/llvm/prebuilt/darwin-x86_64/sysroot/usr/lib/aarch64-linux-android/34
msvc_lib_dir=
kernel32_lib_dir=

```

Notes vs the iOS libc file: `sys_include_dir` is the per-triple subdir (holds `asm/`), and `crt_dir` **must** be set (`crtbegin_so.o`/`crtend_so.o` live there). There is NO `libpthread` in bionic (folded into libc). x86_64 variant: swap `aarch64`→`x86_64` in the two triple dirs. Long-term this file is generated by the MSBuild target (Step 4); for Steps 1–3 keep a manual copy (e.g. current session scratchpad or an untracked local file).

Known propagation gaps (fixed in Steps 2–3, listed here so failures are diagnosable):
- `zig build --libc/--sysroot` propagates to child `zig build-lib` steps but **NOT to translate-c** steps → SDL header translation needs explicit include paths (Step 3, edit 2).
- System-library search paths are **not** derived from sysroot/crt_dir → `-llog` fails with `searched paths: none` until an explicit `-L <sysroot>/usr/lib/aarch64-linux-android/34` is added (Step 3, edit 3).

## Step 3 — Engine-side edits (zaudio pkg, build.zig, root.zig)

### 3.1 Vendored zaudio build.zig

zaudio links `-lpthread -lm -ldl` unconditionally on linux — this is the verified first wall (`unable to find dynamic system library 'pthread' … searched paths: none`). Bionic has **no libpthread**; m/dl are covered by zig's `link_libc` on android targets (probe-verified: zig auto-adds libdl DT_NEEDED, math → libm). Fix: in `Zigote.Engine/zig-pkg/zaudio-*/build.zig`, gate all three `linkSystemLibrary` calls with `!target.result.abi.isAndroid()`. (miniaudio.c itself compiles clean with the libc recipe — verified standalone.)

### 3.2 `Zigote.Engine/build.zig`

1. **translate-c include fix** (l.360–365): the `sdl_system_include_path` arm currently gated `os.tag == .ios` (fed from `b.sysroot`) — extend to android, passing `<sysroot>/usr/include` to the SDL wrapper module. This fixes the verified translate-c failure (`SDL_stdinc.h:52 'string.h' not found` — `--libc` is not propagated to translate-c). If translate-c then trips on `asm/*.h`, the per-arch dir `<sysroot>/usr/include/<arch>-linux-android` is also needed — the wrapper accepts one path, so mirror the two-path trick inside the wrapper package.
2. **System-lib search path**: for android targets add `addLibraryPath(<sysroot>/usr/lib/<arch>-linux-android/34)` on the engine module before its `linkSystemLibrary("log")`/`("android")` — search paths are NOT derived from sysroot/crt_dir (verified fix for `-llog … searched paths: none`).
3. **`linkWgpuNative` android arm (l.83–91)**: add one line, `mod.linkSystemLibrary("unwind", .{});`, mirroring the desktop-linux arm at l.90. The wgpu_android archive references the full `_Unwind_*` set (Rust panic path) which bionic doesn't export; zig satisfies it from bundled LLVM libunwind (empirically link-verified). NOT needed: `c++_static`/`c++abi` (zero `__cxa_*` refs), `aaudio`, EGL/GLESv2/vulkan (all dlopen'd at runtime). `log` isn't needed by wgpu itself but stays (SDL/engine need it).

### 3.3 `Zigote.Engine/src/ffi/root.zig`

1. **Android main inversion** (near `run_app_main`, ~l.1053; mirrors `zigote_run_app` at l.1071):
   ```zig
   var android_main: ?*const fn () callconv(.c) i32 = null;
   export fn zigote_set_android_main(f: *const fn () callconv(.c) i32) void { android_main = f; }
   export fn zigote_android_main(argc: c_int, argv: [*][*:0]u8) c_int {
       _ = argc; _ = argv;
       return (android_main orelse return 1)();
   }
   ```
   On Android, Java calls in (SDL's `nativeRunMain` dlsyms `zigote_android_main` and wraps it in `SDL_RunApp`) — the managed side must NOT call `zigote_run_app` there. iOS keeps its existing inversion. No ABI bump. Regenerate the C# P/Invoke bindings from root.zig afterward (they are generated, not hand-written; watch the known generator `out`-param trap).
2. **Surface recreation on foreground** (poll lifecycle arms, l.1334–1343; android-only via `comptime abi.isAndroid()`): before emitting `EVT_APP_FOREGROUND` on `.did_enter_foreground`, call a new `recreateAndroidSurface(state)`:
   - read `SDL_PROP_WINDOW_ANDROID_WINDOW_POINTER`; if null (resume raced `surfaceCreated` — shouldn't happen given SDLActivity's gating, belt-and-braces) set a `surface_lost` flag and retry on later polls;
   - release any held `wgpu_backend.current_view`/`current_surface_texture` (normally null between frames);
   - `state.surface.unconfigure(); state.surface.release();`
   - `state.surface = try createNativeSurface(state.instance, state.window, null)` — the existing android arm (l.691–695) already reads the refreshed property (SDL refreshes it on every `surfaceCreated`, SDL_android.c:1240);
   - refresh `wgpu_config.width/height` from `window.getSizeInPixels()` (rotation while backgrounded), reuse format/present/alpha, `configure`;
   - **`state.wgpu_backend.surface = state.surface`** — critical: WgpuBackend holds the surface BY VALUE (wgpu_backend.zig:17, wired at root.zig:945); miss this and it presents the dead surface forever.

   Rationale (verified): no SDL event signals surface loss on the external-graphics path (`RENDER_DEVICE_RESET` is GL-only); background/foreground IS the protocol. `nativeResume` fires only after `mIsSurfaceReady && focus && resumed`, so the new ANativeWindow is already in the property by the time `.did_enter_foreground` lands. `SDL_HINT_ANDROID_BLOCK_ON_PAUSE` (default on) parks the thread inside `zigote_poll_events` while paused; C# already handles this (App.cs:1130 `IsPaused` drain-only). The Vulkan loader `ANativeWindow_acquire`s the window, and `WgpuBackend.acquire` already maps `.lost/.outdated/.timeout/.occluded → .skip` (wgpu_backend.zig:62–66) — no crash window.
3. **Optional**: on `.will_enter_background`, `state.surface.unconfigure()` only (frees swapchain memory; not needed for correctness).
4. **Self-heal fallback**: if android and not paused, N consecutive `.skip`-with-`.lost` acquires → run `recreateAndroidSurface` again (covers DeX/split-screen surface swaps without a pause). N unspecified — pick (e.g. 3) and note.
5. No new FFI export required; optionally add `zigote_recreate_surface(handle) -> ZgStatus` as a manual test hook.

## Step 5 — .NET Android head project

**Decision (Report 3): managed SDLActivity subclass — no Java subclass, no Application hack.** Boot chain: zygote → MonoRuntimeProvider ContentProvider inits Mono → managed `ZigoteActivity : Org.Libsdl.App.SDLActivity` → overridden `LoadLibraries()` loads **libzigote.so only** (SDL's `JNI_OnLoad` is linked inside it) then registers the managed entry via `zigote_set_android_main` → SDLThread → `nativeRunMain(...,"zigote_android_main",...)` → dlsym → reverse-P/Invoke into the managed app entry, which runs Gallery via MobileHost. Single .so: no separate libSDL3.so/libmain.so.

Files (place alongside the existing mobile scaffolding from commit a6c7bc8 / `docs/mobile-port.md` layout, e.g. `mobile/android/`):

1. **Vendored Java** — NOT in the zig-pkg (castholm strips `android-project/`). ## Report conflicts (explicit — decide, don't inherit silently)

- **C1 — API level (34 vs 26).** Report 1 pins everything at **API 34** (crt_dir `…/34`, target `.34`, matches emulator image; probe-verified). Report 2 probe-verified the HAVE_ table at `__ANDROID_API__` 24/26 and gates `HAVE_NL_LANGINFO`/`HAVE_ST_MTIM` on minSdk ≥ 26. Report 3 sets **minSdk 26** (`SupportedOSPlatformVersion`). Compiling native code at `__ANDROID_API__=34` while shipping minSdk 26 can produce strong references to 27+ bionic symbols that don't exist on older devices. This plan uses **.34 for bring-up** (emulator is API 34, recipe verified verbatim) — but the ship configuration must either drop the native target/crt_dir to `.26` (and re-run the Step-3 probe) or raise minSdk to 34. Unresolved; revisit before any device broader than the emulator.
- **C2 — libm/libdl linkage.** Report 1: linking them as system libs needs an explicit `-L`; Report 4: zig's `link_libc` covers m/dl automatically on android. Plan resolves by **removing** `-lpthread -lm -ldl` from zaudio for android (satisfies both reports); the explicit `addLibraryPath` remains required for `log`/`android` (Report 1, empirical).
- **C3 — SDL file dialog backend.** Within Report 2: dummy dialog chosen (mirrors iOS; in-app FileBrowserDialog exists) vs compiling `SDL_androiddialog.c`. Exactly one may be compiled (duplicate unguarded symbol). Plan picks dummy; flip is a 2-line swap later.

## Risks / open questions

1. **Binding generator vs SDLActivity.java** (~2,230 lines, inner classes, protected members). Mitigate: `Bind=false` on the 10 support files; only `getLibraries`/`getMainFunction`/`loadLibraries` must bind. **Fallback (design A):** all Java `Bind=false`, a 6-line Java `ZigoteSDLActivity` subclass as the launcher (via `AndroidManifestOverlay`), registration moved to a managed `[Application]` subclass `OnCreate` (verified to run before any activity).
2. **JNI symbol stripping**: `Java_org_libsdl_app_*` + `JNI_OnLoad` must survive in libzigote.so (no gc-sections/visibility loss) — checked in Step 3's `llvm-nm -D` gate.
3. **Activity re-creation vs managed statics**: keep `nativeAllowRecreateActivity()` default (=`System.exit(0)`); the C# app cannot re-enter main twice per process.
4. **`dlclose` after main returns** while Mono holds DllImport handles — refcounted, benign, but don't cache native fn ptrs past app-main return.
5. **Reverse P/Invoke from unattached SDLThread**: Mono auto-attaches; if SGen misbehaves, swap `[UnmanagedCallersOnly]` for `Marshal.GetFunctionPointerForDelegate` (SDL2Droid-CS-proven).
6. **ModuleInitializer ordering**: if any Zigote ModuleInitializer P/Invokes libzigote before `base.LoadLibraries()`, DllImport dlopens it first — ART still runs `JNI_OnLoad` on the later `System.loadLibrary`, but keep registration ordered after `base.LoadLibraries()` anyway.
7. **wgpu-native v29.0.1.1 Android prebuilt min-API** unchecked against minSdk 26 (emulator API 34 is fine). Its weak-undefined syms (`memfd_create`, `getrandom`, `gettid`, …) impose no link/min-API constraint.
8. **Probing the wgpu .a**: ~116 members are LLVM 21 bitcode — NDK 26's LLVM-17 tools produce wrong/partial symbol lists; use Homebrew `llvm@21` (or trust zig, same LLVM) for any future archive inspection. Extracted analysis artifacts in `.../scratchpad/wgpu-android/` (session-scoped, may be gone).
9. **gfxstream immediates feature**: push constants should be granted; root.zig:836 warn line is the canary.
10. **Surface-recreation edge cases**: property-null on resume (belt-and-braces retry flag included), and the self-heal threshold N for lost-acquire recovery is unchosen.
11. **Translate-c arch include**: the SDL wrapper takes one include path; if translation fails on `asm/*.h`, mirror the two-path trick inside the wrapper (Step 3.2.1).
12. **SDL audio dormant / miniaudio runtime**: SDL's AAudio driver is compiled but unused; miniaudio's Android runtime backend compiles but is **untested at runtime** — first audio playback on emulator is an open checkpoint.
13. **HIDAPI stubbed**: no USB/BLE gamepads until `.SDL_HIDAPI_DISABLED` is flipped (deliberate deferral).
14. **.NET Android workload** not yet installed (Step 0); `net10.0-android` TFM, javac/d8, manifest merger, MonoRuntimeProvider injection and `-t:Run` fast-deploy all come from it.
15. Project-level: pre-existing test failures (native-flecs 78/818) are unrelated — don't chase; commits carry the project identity, no AI attribution.
